# ADR：员工与各自文件记忆

日期：2026-10-20（America/Los_Angeles）。状态：采用于当前 checkout；其他聊天待显式同步。任务：MEM-01。

## 用户目标

用户明确要求打开并修改项目 agent.md，重新设置 Agent 员工，为每个员工建立独特记忆库。实际项目入口为 AGENTS.md。按此授权调整共享规则和支撑文档，保留产品及历史工作。

## 决定

- 采用现有 lead、frontend、backend、qa 四个日常角色，rules 为按需专家。frontend 合并旧 shell/features；code_review 是 qa 别名。
- 根 AGENTS 管共用规则；memory/<角色>/PROFILE.md、MEMORY.md、HANDOFF.md 分别管身份、长期经验、下次交接。status 对外报进度，TASKS 派工/定所有权，decisions 管正式跨角色决定。
- lead 在 MEM-01 一次性初始化五个角色的三个文件；此后角色只写自己的记忆，lead 只维护共享说明和入口。各角色种子只引用已有文档，不导入个人对话或健康数据。
- current/<角色>.md 是当前启动入口；旧 prompt 顶部给出历史提示，保留旧内容和旧状态。
- 文件记忆需要在每轮开始/上下文恢复时读取并在交接时更新。角色身份不随模型或工具变化；同角色同一时刻只允许一名写入者。新增身份先登记任务板。
- 沿用独立 worktree。本人提交，lead 审查集成，各 checkout 显式同步；没有未提交文件的实时共享或自动跨聊天加载。
- 这是一套协作目录，不提供加密或账号级访问控制。不得保存真实健康记录、凭据或不相关个人信息。

## 范围与限制

本轮只在当前根 checkout 落实配置，没有发送消息、创建/重启员工、修改已有 worktree 或更改产品实现/API/依赖。其他会话是否运行与采用新配置未经核验。没有新增向量数据库、自动化或模型付费调用。

产品与安全规则保持；旧待修复问题不因重设员工而解决。角色职责改变先由 lead 更新 TASKS，再由该角色维护 PROFILE。当前实际源码/实测与最新人类指令优先于历史记忆。

## 验证

检查五个角色的目录、三文件、入口、链接和所有权一致性；执行 npm run build。实际结果见 status/lead.md。仅文档改动，无 server 变化，未为本轮重复运行产品测试。

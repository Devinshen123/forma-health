## 1. 已确认方向与剩余决定

面向全球用户，核心是健身表现与长期健康；简体中文与英文；Web 与真正的 iPhone App 共用账户、数据模型与服务；第一版 iPhone 接入 HealthKit。Apple 登录与邮箱登录已确认；分发选择网页邀请测试和 TestFlight。前期获客、后期收费，意向价格 **US$20/月**。用户确认已有 Mac/Xcode 和 iPhone，具体版本与远程访问尚待验证；Apple Developer Program 会员、整体服务预算未确认。

当前目标不是替用户作医疗决策，而是把饮食、训练、睡眠与主观状态连接成当天能做、能改、能理解原因的行动。引导 → 用户确认计划 → 审核饮食 → 记录训练 → 记录睡眠/状态 → 确认或撤销调整 → 每周复盘，是核心连续体验。

仍需集中决策：首发服务地区与年龄范围；每月服务预算；HealthKit 只在设备处理、上传摘要还是允许原始样本上云；照片与报告保留期限；托管邮箱认证形式；AI/OCR 供应商及其健康数据处理条款；首版食谱、周菜单与购物清单的范围。推荐先服务成年健身用户，邀请测试按地区逐步开放；HealthKit 原始样本优先留在设备，只在独立同意后上传最小必要摘要。全球目标不等于已经通过所有地区的可用性与合规核查。

## 2. 第一版 PRD 与用户价值

**首批用户假设**：已有一定健身意愿，但饮食、训练和睡眠分散在多个工具里的成年人；包括 Apple Watch 用户，也允许没有设备的人手动记录。目标分为健身表现、力量进步、持续习惯，不能把所有用户默认归为美国减脂人群。

**差异化假设**：用户并不只需要多一个仪表盘，而是需要知道今天做什么、为什么适合当前情况，以及时间/状态变化后怎样作一个可撤销的小调整。计划参数与事实记录分开保存，既能解释，也能防止一次自动建议覆盖历史。

验证方式：邀请用户完成整条流程，观察引导确认、审核保存、实际训练/睡眠记录、调整接受与撤销、次周回访；访谈用户哪些调整省时、哪些造成负担。支付意愿需通过真实付费意向与留存验证，不能把点击价格按钮视为订阅已成立。产品指标使用最小必要事件，健康原文、照片和报告不进入普通分析日志。

| 领域 | 完整 MVP 行为 | 网站本轮落实范围 |
| --- | --- | --- |
| 引导 | 六步问卷、返回、草稿、适当跳过、解释与确认 | 目标、经验/时间/器械、偏好与限制、睡眠目标、可选自填营养目标、计划确认；账户草稿隔离 |
| 饮食 | 相机/图片/文字/手动；AI 候选审核、份量编辑、历史与汇总 | 图片上传与真实手动/标签营养录入、份量换算、审核保存；未接 AI 时不假造识别结果 |
| 训练 | 个性化模板、动作/组次/负重、替代、记录与趋势 | 根据用户参数展示固定模板与真实训练记录；不复制未获许可的媒体 |
| 睡眠/状态 | HealthKit 或手动、来源、同步状态、缺失/重复/时区 | 手动起止时间、精力/感受；HealthKit 标记依赖 iPhone，网页不伪装读取 |
| 计划与调整 | 参数可编辑、原因与差异、确认、版本、撤销 | 手动编辑生成版本；用户主动选择缩短每次训练后审核 30 分钟固定候选；接受/拒绝/补偿版本撤销 |
| 今日与趋势 | 当日行动、指标解释、7/14 日图表、完整度 | 实际记录汇总、点击日期查看详情、缺失不填零、记录覆盖不冒充健康分数 |
| 报告 | 主动上传、OCR 项目/单位/日期/原范围、人工校正、解释与趋势 | 私有上传及人工录入核对；OCR/医学解释未接通时清楚说明 |
| 周复盘 | 执行、记录覆盖、主要变化、少量下周行动 | 基于实际记录的确定性复盘；明确未调用 AI，不写因果或诊断 |
| 账户与隐私 | 双端同一账户、独立同意、导出、删除 | 本地服务账户与数据隔离、持久化、导出/删除；Apple 认证等待开发者账户配置 |

完整 MVP 是后续验收目标。本轮网站里程碑优先把可运行的记录与审核链路做好，其余真实服务依赖清楚保留；不会把静态演示或固定规则称为已工作的 AI。

不纳入本轮：Android、watchOS 独立 App、WHOOP/医疗机构同步、购物交易、预约、诊断/用药、延寿保证、开放所有地区、正式订阅收费。食谱与购物清单没有被默认为已确认需求。

## 3. 页面与关键流程

| 页面 | Web | iPhone 计划 |
| --- | --- | --- |
| 账户与语言 | 登录/注册、中文英文切换、演示入口 | Apple/邮箱登录、语言与单位 |
| 引导 | 6 屏、草稿、初始计划确认 | 原生分步界面、设备连接按需解释 |
| 今日 | 今天的行动、摄入/训练/睡眠、最近记录、调整入口 | 同一内容，增加原生快捷记录 |
| 饮食 | 上传、人工审核、份量、历史 | 相机/相册、多模态候选审核 |
| 训练 | 模板、组次负重/时长/感受、记录 | 原生训练执行、记录与替代动作 |
| 睡眠 | 手动起止时间和主观状态 | HealthKit/手动、同步时间/来源/权限空结果 |
| 计划 | 参数、差异审核、历史、撤销 | 共享相同计划版本与确认语义 |
| 趋势 | 7/14 天、可点击日期、记录覆盖和复盘 | 同一统计契约的原生图表 |
| 报告 | 私有上传、人工核对、原值/单位/范围 | 原生上传/查看，OCR 核对流程 |
| 设置 | 语言、单位、时区、隐私、导出、删除 | 增加健康连接管理与通知频率 |

关键闭环：

1. 新账户从空数据开始；演示数据只留在明确标注的独立演示模式。
2. 用户填写问卷，营养目标可以留空；计划来源说明为问卷与固定模板，确认后启用。
3. 饮食数值按参考重量计算，用户审核食物/份量再保存；识别失败时仍能手动录入。
4. 用户记录实际训练和手动睡眠。缺失显示为未知，睡眠按醒来日保存，重叠区间避免重复累计。
5. 用户主动选择缩短每次训练，固定规则提出 30 分钟候选，先展示理由与前后差异，并说明今后训练也使用这个目标。接受新增计划版本，拒绝保留原安排；当前契约没有仅当日覆盖模式。
6. 当前已接受调整可撤销，新增一个恢复原参数的补偿版本；餐食、训练与睡眠事实保留。
7. 7/14 日趋势显示真实保存的记录；复盘先说明记录覆盖，再给少量可选行动。

视觉采用自有 Forma 品牌：冷灰背景、白色内容卡、深色文字、浅绿色重点、克制的图标与层级。学习 Apple 的可读性与原生交互、Cal AI 的饮食审核简洁性、LADDER 的引导与训练连续性；不是复制品牌、原图或私人 API。设计依据：[设计规格](design/design-system.md)、[桌面概念](design/dashboard-concept.png)、[移动饮食概念](design/mobile-meal-concept.png)。概念图是设计参考，不是运行截图。

## 5. 技术方案与统一契约

**本地网站验证方案**：React/TypeScript 界面、TypeScript 服务端 API、SQLite 持久层、本地私有文件存储。账户状态保存采用版本条件检查；记录更新、建议决策和计划版本变化在服务端校验。演示状态与登录账户隔离。这个选择服务于本机真实验证，不代表浏览器 localStorage 就是后端，也不适合直接把文件系统换成无持久盘的生产环境。

**后续托管候选**：保留同一 API 与模型，迁移托管 PostgreSQL、私有对象存储、任务队列/作业、服务端 AI/OCR、SwiftUI iPhone 客户端。托管供应商与地区、预算和数据处理条款待确认；服务端需要批次幂等、用户/设备隔离、云同步同意、删改与失败重试。SQLite 与 JSON 状态快照向领域表/事件迁移须有版本和校验，不把本机储存格式当作长期跨设备同步协议。

统一对象：Profile、Meal、Workout、Sleep、Report/Marker、PlanVersion、Suggestion、Consent/DeviceConnection（后续）。事实记录与建议分开。计划版本只追加，关键修改保存 base version、diff、reason；接受和撤销都校验当前版本。接口大类包括 auth、state/revision、private assets、plan/suggestion decisions、exports/deletion；后续再拆健康 batches、reports/extract 与 jobs。详细字段、接口、HealthKit 锚点、删除传播、隐私与设备依赖见 [HealthKit 架构研究](research/healthkit-architecture.md)。

确定性逻辑负责份量/营养计算、单位换算、统计、过敏与限制过滤、权限和校验；AI 负责候选识别、草稿和表达。AI/OCR timeout、结构校验失败、限流时可回到手工。密钥不进入 Web/App；敏感内容不进入普通日志。原始报告范围与单位保留，OCR 修正先于解释。

国际化：本轮组件为类型约束下的中文/英文字典，包含错误、空数据、按钮和可访问性文案；数字、日期由 Intl 格式化，语言与时区/单位独立。以后可迁移统一 locale namespace，不能用简单翻译取代食品名称、单位和地区可用性验证。引导草稿按当前账户与演示模式分 key，退出清理，不能串入另一个账户。

## 8. 验收、风险与真实性清单

本地网站必须验证：注册/登录与两账户隔离；引导返回/跳过/草稿与确认；份量换算及持久化；训练和跨午夜睡眠；中英文切换；空记录与真实零；计划差异、接受/拒绝/补偿版本撤销；重复写入/冲突与失败；私有上传/越权访问；导出/删除；移动宽度、键盘与 modal 焦点。服务端持久化与计划事务通过实际 API 测试，界面通过浏览器流程检查。

不能宣称由本轮网站验证的项目：HealthKit 真机权限/锁屏/后台/删除同步；Apple 登录开发者配置；TestFlight 安装；多模态食品识别；报告 OCR 或医学解释；外部穿戴/医院同步；托管生产安全与地区合规。

| 分类 | 本轮内容 | 必须如何标记 |
| --- | --- | --- |
| 可运行功能 | 本地账户、持久化、手工记录、份量计算、上传、计划版本与记录趋势 | 以 build/API/browser 测试的实际结果更新运行说明；不能仅以组件存在判通过 |

| 固定规则 | 初始训练模板、缩短每次训练候选、统计复盘 | 明说未调用 AI，展示用户输入与原因 |
| 外部服务依赖 | Apple 登录、HealthKit、AI/OCR、托管邮件、正式部署 | 保留未接通状态与手动替代，不 fake 成功 |

主要风险：照片估算误差与用户审核负担；记录不足导致误读；计划更新的跨端冲突；健康授权、第三方 AI 与删除语义；源码/素材许可证；托管地区和预算；HealthKit 后台可靠性。方案通过显式来源、缺失状态、候选确认、版本与手动回退降低风险；不凭一个睡眠指标作医疗判断，不承诺确定健康效果。

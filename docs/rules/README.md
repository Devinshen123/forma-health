# 规则层说明（`server/rules/`）

- 负责人：rules（Claude Code）
- 引擎版本：`ENGINE_VERSION = 1`
- 更新：2026-10-14
- 运行测试：`node --import tsx --test server/rules/*.test.ts`

## 原则

1. **纯函数**：不做 I/O，不读时钟，不用随机数。`today`、时区、id 和时间戳都由调用方传入；同样的输入一定得到同样的输出（有测试）。
2. **缺失不等于零**：没记录的天、未知的营养素保持 `null`，并标注 `partial` 或完整度。聚合时排除未记录的天。
3. **只用已确认的记录**：AI 草稿不进入规则计算。
4. **每条输出都可解释**：带 `reason { key, params }`、证据引用（`evidence[]`，最多 10 条，按日期从新到旧），以及完整度。
5. **数据不足就不说话**：返回 `insufficient_data`，不猜。
6. **计划改动只是提议**：要用户接受；接受时校验 base 版本，不一致返回 409；撤销会新建一个恢复版本。
7. **今日行动都是可选项**：每天最多 3 条，按优先级排序，其余记为 `limit_reached`。

## 模块

| 文件 | 内容 |
|---|---|
| `nutrition.ts` | 按克数缩放、汇总（保留 null，标记 partial）、kcal/kJ、g/oz、kg/lb 换算、展示用取整、宏量与热量一致性提示 |
| `days.ts` | 按时区取本地日期、日期运算（与夏令时无关）、按日汇总饮食、只按已记录天求平均、睡眠按醒来日期归档（重叠合并，拒绝不可能的时段） |
| `plan.ts` | 计划 diff、取值范围（与计划编辑页一致）、应用 patch、base 检查、补偿式撤销 |
| `safety.ts` | 18 岁门槛、保守模式、引擎可改字段的白名单、单次上调幅度、过敏原“可能冲突”提醒 |
| `engine.ts` | 提议和今日行动的规则、去重、冷却期、上限；`toSuggestion()` 转换为现有的 `Suggestion` 结构 |
| `messages.ts` | 中英文理由模板；缺模板或缺参数时直接报错 |

## 规则目录

### 计划改动提议

所有提议的公共门槛：
- 必须有计划，且计划已创建满 7 天；
- 同一字段已有待处理的建议时不再提出；
- 同一规则被拒绝或撤销后 14 天内不再提出；
- 每次最多 2 条，同一字段只出现一次；
- 必须通过 `guardEnginePatch`。

| ruleId | 窗口 | 数据充足条件 | 触发条件 | 提议 |
|---|---|---|---|---|
| `training.minutes_down` | 最近 14 天（含今天） | ≥3 次时长 > 0 的训练 | 时长中位数 < 计划 × 0.75 | 改为中位数（取到 5 的倍数，≥10），且至少比原计划少 10 分钟 |
| `training.minutes_up` | 同上 | 同上 | 时长中位数 > 计划 × 1.25 | 提高到 min(计划 + 15, 中位数取到 5 的倍数, 180)，且至少增加 10 分钟；保守模式下禁止 |
| `training.days_down` | 最近 4 个 7 天区间 | 至少 3 个区间有记录到的训练 | 每个区间的训练天数都 < 计划 | 改为 max(1, 平均值四舍五入)；理由中写明“只按已记录的训练计算” |

### 今日行动（可选，最多 3 条）

| 优先级 | ruleId | 数据充足条件 | 触发条件 | 说明 |
|---|---|---|---|---|
| 1 | `recovery.lighter_option` | 今天醒来对应的睡眠有记录 | 睡眠 < 5 小时，**并且**精力自评 ≤ 2 | 需要两个信号同时满足；只是可选项，**不取消训练，也不改计划** |
| 2 | `training.session_today` | 有计划 | 最近 7 天的训练天数 < 计划，且今天还没训练 | 写明计划次数和已完成次数 |
| 3 | `nutrition.protein_gap` | 昨天往前 7 天中，≥4 天有 2 餐以上且蛋白质完全已知 | 这些天的平均 < 目标 × 0.85 | 理由提示“可能有漏记” |
| 4 | `sleep.wind_down` | 最近 7 天有 ≥4 晚记录 | 平均 < 目标 − 0.75 小时 | 建议“今晚提前 30 分钟准备休息” |
| 5 | `logging.meals_insufficient` | — | 昨天往前 7 天中，有饮食记录的天数 < 3 | 保守的补记提示，说明记录不足时不给饮食建议 |

## 与现有契约的接口

- `toSuggestion()` 输出现有的 `Suggestion`：`reason` 是理由的 key（例如 `rule.training.minutes_down`），`patch` 只含 `trainingMinutes` 或 `trainingDays`。
- **证据、参数和完整度目前会丢失。** 需要契约扩展，已向 lead 提出请求。
- 前端用 `renderReason(reason, lang)` 渲染理由，或者使用同一份模板的拷贝。

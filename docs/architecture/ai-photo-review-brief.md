# AI photo integration review brief

Forma is an existing local Vite React19 / Express5 / TypeScript website. Do not assume cloud infrastructure. Human requested food photo recognition and chose to finish integration before configuring a key. No live calls, enrollment, or billing activation are part of this change.

Review this concrete design for missed correctness or privacy issues; return at most five actionable findings with a brief explanation. This is a design-only brief, not source code inspection.

- Existing session cookies and X-Forma-Account header protect every new endpoint. POST food-photo-drafts accepts only owned private assetId, explicit per-photo consent:true, and zh/en. External URLs, user IDs, arbitrary models are rejected.
- JPEG/PNG/WebP <=5MiB, decoded <=20MP; Sharp rotates, shrinks to longest1024 and reencodes JPEG removing EXIF. Only normalized photo + outputlanguage are sent. User profile, allergy, account, training, sleep, reports are never in the model request.
- Fixed OpenAI Responses gpt-5.4-mini-2026-03-17, reasoning:none, image high, store:false, max2000out; strict structured schema followed by server Zod validation. At most8 items with name, estimatedgrams, per100g kcal/protein/carbs/fat. Unknown numbers null, nonfood false+emptyitems. No score, diagnosis, allergen safety assertion, invented confidence or cause inference.
- Raw validated draft stored separately and immutably with owner, asset and provider/model. No meal is saved by inference. User edits/removes items and fills missing values. Confirmed entries carry ai_estimate + draftId + original itemindex + matchingasset + reference100. Server verifies provenance. Deterministic math converts edited baseline and portion. User-edit values remain distinct from raw model draft.
- One active request/account, 5requests/minute, 10/UTCday. SQLite reserves US$0.02 before every actual attempt including retries, default US$0.40/day. Failure not refunded. At most1 retry for network/timeout/429/5xx; no retry for refusal/auth/invalidoutput. Model fixed, normalizedpixelbounds and outputcap keep conservative reserve, currentpricing reviewed. Reserve is application estimate, not provider actualbill. Locks expire after total boundedattempttimeout.
- Missing key and provider errors have safe typed bilingual UI messages/manualfallback; no errorpayload/log echoes key/image/healthcontent. Configpresence is not connectionverified. Client AbortSignal plus run generation ignores stale replies; upload freezes expectedaccount before FileReader. App remounts photo screen byaccount. Abort may not stop a vendor bill.
- Export includes rawdrafts+reserveledger; deleting unused asset cleans itsdraft, deleting account cascades all. End-inference rechecks asset/owner existence. Raw records unaffected by plan revisions. SQLite remains local and not app-level encrypted.

# 设计对照与允许差异

设计依据 dashboard-concept.png 与 mobile-meal-concept.png，原始生成图由 view_image 以 original 尺寸检查。实现 desktop-render.png（1440×1000）与 mobile-render.png（390px宽）由 Playwright/Edge 无头独立上下文截图并用 view_image 原尺寸检查。内置浏览器完成操作流程，但截图接口初次成功后连续返回 Unable to capture screenshot；因此截图使用可用的本机 Playwright，没有访问被拒的 Cal AI 网站。

| 对照点 | 设计依据 | 实现与修复 |
|---|---|---|
| 布局 | 固定左栏，今日主区＋周趋势侧栏 | 桌面按同一两列模型实现；手机单列与底部导航，原尺寸核查 |
| 字体层级 | 系统字体，标题/hero/指标明显，次要说明克制 | 系统字体、32px标题、28pxhero/指标；功能页面修复默认h1导致的过大字级 |
| 配色与材质 | 冷灰背景、白面板、石墨hero、薄荷绿 | 统一tokens，保留轻边框与圆角；未加第三方图片覆盖或色彩滤镜 |
| 手机断行 | hero分成“今天，”与“保持你的节奏。” | 已修复断字；最终390×844截图原尺寸复查，无页面横向溢出。截图禁用过渡动画以避免抓取视口切换中的半露侧栏 |
| 图标 | 简单outline，水平哑铃、月亮、餐具、箭头 | Lucide 1.75px；哑铃旋转为水平，保留语义和操作区域 |
| 容器与间距 | 16px圆角、主区与侧栏关系 | 共用panel/button/field；16–24px间距，表单与对话框沿用设计系统 |
| 操作 | 用户主导，编辑、确认与撤销 | 真正的数据库保存、原生dialog焦点与Esc、版本化调整；无自动AI变更 |
| 图片 | 最近饮食一个清楚的食物缩略图 | 独立生成的示例食物图；真实账户只有自己的附件，不拿示例照片替代记录 |

首屏文案对照：主要标题、导航、CTA与区域顺序保留。允许的功能性差异：周图按真实最近7天与记录绘制，缺失为—而非生成图零值；2/3进度对应真实示例两项完成，修复概念内状态不一致；“3个动作”改“按你的节奏”避免无真实训练计划细节；“今天调整30分钟”改“每次训练调整”以准确反映持久计划参数；添加数据来源/缺失说明；原始生成手机版自行添加的热量目标不使用。

饮食表单增加营养标定重量、日期与来源、实际摄入预览，这是正确份量换算所必需的用户控件，保留原概念的清晰层级与审核保存路径。不会把概念中的示例营养数据预填给真实新用户。

当前设计按以上明确允许差异忠实实现；任何尚未完成截图/交互的区域仍应在最终验收记录中注明，不笼统声称像素级完全相同或生产服务已接入。

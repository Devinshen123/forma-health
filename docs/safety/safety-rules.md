# 安全规则（草案，待营养师审核）

- 状态：`draft_pending_dietitian_review`（代码中为 `SAFETY_REVIEW_STATUS`）
- 更新：2026-10-14
- 负责人：rules（Claude Code）
- 注意：本文件和 `server/rules/safety.ts` 只是工程上的保守默认值，**不是**医学或营养学结论。数值进入正式邀请测试之前，需要有资质的营养师审核；审核记录写在本文件末尾。

## 1. 适用人群

- **仅限 18 岁及以上**（用户已确认）。只知道出生年份时，取可能的最小年龄判断：
  - 最小年龄 ≥ 18 → 可以使用；
  - 最大年龄 < 18 → 不能使用；
  - 处在临界那一年 → 必须填写完整出生日期。

  对应 `ageEligibility()`。
- **保守模式**：问卷中任一项为“是”就启用，`conservativeMode()` 会记录所有触发原因：
  - 怀孕或哺乳；
  - 有进食障碍史；
  - 肾病；
  - 正在使用降糖药或胰岛素；
  - 正在接受其他医疗照护。
- 保守模式下：
  - 规则引擎不提出任何**增加训练量**的改动；
  - 计划页提示“请与医生或营养师确认目标”；
  - 不显示热量赤字相关的内容。

## 2. 热量与营养目标

- 规则引擎**永远不会自动修改热量或蛋白质目标**（`ENGINE_PROPOSABLE_FIELDS` 只包含 `trainingMinutes`、`trainingDays`）。这两项只能由用户本人修改。
- 表现类目标（performance/strength）默认不设热量赤字。
- 待营养师确定：
  - 每日热量下限；
  - 每周减重速度上限（文献中常见每周体重的 0.5–1%，**未审核**）；
  - 蛋白质每公斤体重的克数区间；
  - 低能量可用性（RED-S）的提示条件。
- 记录到的摄入明显偏低时，先问“是否有漏记”，不下结论。漏记不等于没吃，也不等于在断食。

## 3. 训练

- 单次自动提议，训练时长最多上调 15 分钟，每周训练天数最多上调 1 天。下调不设上限，但必须由用户确认。
- 单一睡眠指标或单一主观感受**不会**取消或改动训练。只有睡眠 < 5 小时**和**精力 ≤ 2 同时出现时，才给出“可以降低强度”的可选提示。
- 有伤病或限制时，动作替换的规则另写（尚未实现）。

## 4. 过敏

- 只把用户声明的过敏原与食物名称、配料文字做比对，结果写作“可能含有”。
- **永远不显示“安全”“不含过敏原”**。照片识别看不到隐藏配料。界面需要配合说明文案（`allergen.not_a_safety_check`）。
- 已覆盖中英文同义词和常见的误判。例如“蛋白质”不算蛋，“荞麦”不算小麦，“椰奶”不算乳制品，“贝果”不算贝类。宁可多提醒，也不漏提醒。

## 5. 化验单（后段切片，规则尚未实现）

- 只使用报告上印的参考范围，不套用通用范围。
- 单位换算需要按指标区分的系数表；没有系数就不换算，并标注“单位不同，不可直接比较”。
- 跨实验室或检测方法的数据，标注“不可直接比较”。
- 报告上有危急值标记（例如 H!!、Critical）时，只提示“请尽快联系医疗人员”，不做任何解读。
- 报告里的文字一律当作数据处理，不当作指令执行。
- 不诊断、不开药、不改治疗方案。

## 6. 文案

- 不说“因为 X 所以 Y”，只说“你记录了什么”和“可以试试什么”。
- 数据不足时明确告诉用户，并给出保守的可选行动。
- 不使用“超标”“失败”这类带评判的字眼。

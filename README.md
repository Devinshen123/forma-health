# Forma · 本机健康与健身网站

当前版本将饮食、训练、手动睡眠和趋势放在同一个网页里，提供简体中文与英文界面。已实现本机账号、首次计划、记录编辑删除、私有照片/PDF附件、计划调整审核与版本历史、周复盘和 JSON 导出。

这是**本机开发与体验版本，尚未生产发布**。AI 食物照片识别已接入服务端接口与审核流程，须配置 OpenAI API 密钥后才可调用。训练和离线同步机制已实现；手机跨设备使用仍需要可访问的共享 HTTPS 服务。OCR、Apple 登录、HealthKit、iPhone App/TestFlight 和收费仍未接入。配置状态由 `/api/capabilities` 如实返回，不代表供应商连接已验证。

## 当前行为

- 未登录显示明确标注的演示数据；创建账户后以空状态开始，不把演示记录存入真实账号。
- 邮箱＋10 位以上密码用于本机登录。**不发送验证邮件，未验证邮箱所有权，也没有密码找回。**
- 饮食支持手动/标签录入与 AI 照片草稿：识别前逐张同意，识别后校正各项名称、份量和每100克营养，确认后才记入饮食；未知值保持空白，需补全才能保存。份量换算由代码执行，AI 来源仍标注估算。
- 训练页包含动作库、计划、训练中、进步和导入：884条动作文字（完整876源数据＋8原创基础动作）、肌群/器械筛选、8项原创二维教学示意；其余动作有文字，不伪称有动画。来源与许可见 [记录](docs/architecture/training-source-log.md)。
- 星期模板与连续天数循环日程可编辑；训练模板修改或接受进阶追加版本。逐组实际次数/负重/时长/RPE/RIR、热身、超级组轮次与递减链、可暂停恢复的休息截止时间均可保存；旧汇总不会变成伪造明细。
- 训练负重以 kg 存储，可以显示/输入 lb；目标与实际记录分开。PR、限定1–10次的Epley估算、主肌群完成组来自实际非热身完成组；两次达标产生可解释、可修改的进阶草稿，用户确认后只改新计划。
- 睡眠按手动起止时间和记录时区计算，归入醒来当天，支持跨午夜，拒绝重叠；没有自动睡眠分期或生理恢复测量。
- 报告支持图片/PDF与手动指标，不执行 OCR、诊断或异常医学解释。
- 接受计划调整追加子版本；撤销追加补偿版本，旧版本和实际记录保持不变。
- 网页使用实体版本、删除墓碑和稳定请求编号同步：不同记录合并，同一记录冲突展示双方差异，由用户选择；批次原子保存。旧 `/api/state` 整份revision接口保留兼容。
- 设置中明确启用离线后，健康文字记录与稳定outbox存入当前账户的IndexedDB；静态网站壳、动作库与原创示意由Service Worker缓存，API/照片/PDF不进入共享缓存。断网可刷新并保存，重连验证同一账户后同步；多标签合并队列，同意撤回后旧标签不能重建缓存。退出前有待同步数据需先同步或导出处理，删除账户清理私有缓存。
- 未启用离线时，网络失败的待确认保存仅留在本页，需保持页面打开或导出备份；重复创建前使用顶部同步重试。首次离线使用需先在线登录并启用，在HTTPS或localhost安全上下文运行。

## 数据位置与导出

账号和记录在 `data/forma.sqlite`；私有附件在 `data/uploads/<account UUID>/<asset UUID>`。`data/` 被 Git 忽略。

**SQLite 和附件当前未做应用层静态加密，依赖本机操作系统账户权限与磁盘保护。**密码采用随机盐 scrypt hash，会话数据库只保存随机 token 的 hash；这不等同于健康记录已加密。

`/api/export` 导出服务端已经保存的账号信息、AppState、revision、附件元数据、独立AI草稿及预算预留记录，**不包含图片/PDF文件 bytes，也不包含仍只在客户端的未同步队列**。附件需另外下载；同步面板的待同步 JSON 可保留本地文字变更和引用，但同样没有附件本体。两种 JSON 都不是完整附件备份，也不能代替原文件。训练支持Strong/Hevy/FitNotes英文CSV格式和Forma JSON训练切片导入，浏览器解析、预览校正、排除重复，确认后保存；缺失值不补零，不导入账户/权限/AI来源或外部附件。供应商CSV升级或其它语言header需另行适配；不宣称已用每个供应商的真实文件验证。删除账户会移除记录、AI草稿/预算、附件、同步账与会话。

未配置密钥时不发起 AI 调用。配置后只有用户逐张同意并点击识别才向 OpenAI 发送去 EXIF、缩至最长1024像素的照片，以及输出语言；不附账户信息、过敏、训练、睡眠或化验数据。`store:false` 不等于供应商零保留，应按实际供应商政策处理。原附件和识别草稿保留在本机；没有自动云同步。

## 配置 AI 食物识图

复制 `.env.example` 为项目根目录 `.env`，只在本机填写 `OPENAI_API_KEY`；不要发到聊天、提交 Git 或添加 `VITE_` 前缀。`npm run dev` / `npm start` 自动加载 `.env`，配置后重启本项目服务。演示模式不调用付费 API，需创建或登录本机账户。

固定模型 `gpt-5.4-mini-2026-03-17` 使用 [OpenAI 图像输入](https://developers.openai.com/api/docs/guides/images-vision) 与结构化输出。最大5MiB、20MP的 JPEG/PNG/WebP；不支持HEIC。一次识别最多8项食物，确认后各项分别记录。模糊图片、混合菜、油和酱汁可能估计错误，照片不能证明是否含过敏原。

默认一账户一次在途、5次/分钟、10次/UTC日；每个供应商尝试预留US$0.02、每账户US$0.40/日、项目总额US$2/日，包含最多一次重试。SQLite原子检查两级限额，重启/删除账户不退项目已预留额。这是应用限额记账，不是实际账单或用户认可的运营预算；其他应用调用不在此限额内。可在`.env.example`列出的范围内调整预算。缺密钥、超时、拒绝、无效输出或额度耗尽时可继续手动记录。

既有验证没有配置真实密钥，测试供应商只在验证代码中注入；真实识别质量与供应商账户可用性尚待另行验证。
